# Jev judge calibration — errata 2

Date: 2026-09-20
Refers to: `docs/experiments/jev-judge-calibration-preregistration-2026-09-19.md`, frozen at first-add commit `af669cee`, and `docs/experiments/jev-judge-calibration-errata-2026-09-20.md` (errata 1)
Status: recorded by the operator before the rule described below was run

## Note on the exclusion file

Rule 2 excludes candidates whose repository is a Cejel calibration-frame member. The first exclusion file used by the build was generated by a grep across every file under `docs/calibration` for any repository-shaped value, and held 16,177 entries: the frames' candidate universes and every dependency and workflow reference inside evidence records, as well as the frames themselves. That file did not implement rule 2's definition. It was replaced on 2026-09-20 by the union of `selected[].fullName` across the 23 wave manifests, 3,742 entries. The preregistration is unchanged by this; the instrument was corrected to match its definition. Under the corrected file, segment A alone yields 50 survivors; under the over-broad file it had yielded 46. Both counts are properties of the instrument, not of the rules. The corpus manifest records `frameExclusionCount`, and a build under the corrected file shows 3742.

## What happened

With the corrected file, the build selected 50 base cases and constructed 250 cases, then refused before writing with `not_run: frame_exclusion_leaked_into_output:corpus`. That guard is preregistered: it searches the lowercased corpus bytes for every exclusion entry as a plain substring and refuses without naming the entry.

The cause is a candidate whose own repository passes rule 2 but whose text cites a frame member. A pull request that bumps a dependency names that dependency's repository in its body; the frame was drawn from star-ranked searches, so its members are the repositories most likely to be cited that way. A local scan of the 1,897 cached candidate reads found 34 of the 3,742 entries occurring somewhere in 86 reads (4.5%). Names were not recorded.

The preregistration is inconsistent at this point: the selection rules admit candidates that the output guard can never write. The guard is right to refuse; a corpus that carried a frame member's name would be a disclosure regardless of why the name was there. The inconsistency is resolved on the guard's side.

## Decision

Rule 12, applied after rule 9 and before rule 10: a candidate is excluded if any exclusion entry occurs as a substring of the lowercased bytes of its title, body and evidence record, the same test the output guard applies to the corpus. Its count is published like the others; no name is. A candidate excluded under rule 12 is never sent to the admissibility filter.

The output guard is unchanged. Rule 12 covers candidate-derived bytes only. Bytes added by the construction rules or produced by the rewriter are not covered; a guard refusal after this erratum therefore indicates a source other than candidate text, and is recorded as a new event before any further change.

Every other rule, the filter, rule 11 across the join, the construction rules, the question wording, the threshold, the metrics, the calibration gate and the five predictions are unchanged. The first 50 survivors in pool order over segments A and B are the corpus. The pool is not extended without a further erratum.

Expectation recorded before rule 12 is run: it removes between 3% and 8% of the candidates that reach it, and the corpus completes from segments A and B.

## Bias disclosed

Rule 12 removes pull requests that cite popular repositories, and dependency-bump pull requests cite them most. The corpus therefore under-represents dependency bumps relative to the pool. This does not bear on the questions asked of the judge, which concern claims the construction rules insert, but it is a property of the sample and is stated here so the result does not have to discover it.
